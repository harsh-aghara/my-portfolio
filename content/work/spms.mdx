## What this is

SPMS is a web application used internally at IIIT Pune to manage the entire lifecycle of student projects. Students submit project proposals, faculty review and approve them, and administrators oversee everything across different semesters and project types. The system handles role-based workflows for all three user types. I worked on this during a campus internship from May to July 2026.

## Getting it to production

The system worked fine in local development, but the initial production deployment fell over immediately. CORS was misconfigured between the frontend and backend services, the Vite environment variables weren't set up to distinguish between staging and production, and the OTP authentication flow had a gap that allowed rate-limit bypassing. I fixed all of these before the system could serve real users.

## Query parallelization

The main project dashboard was painfully slow. I profiled the API and found that the endpoint was running over 20 sequential database queries to pull together student data, project status, and faculty approvals. Each query waited for the previous one to finish even though most of them were independent. I rewrote the data fetching to fire independent queries concurrently with Promise.all and verified the improvement with a benchmarking script. The p95 latency dropped 57%, from 97.52ms down to 42.22ms.

## Email and CI

The original email setup used Nodemailer with basic SMTP, which had high bounce rates and kept getting throttled. I migrated to the Brevo API for transactional emails (project approval notifications, OTP delivery). I also set up a CI workflow to automate testing and build validation on pull requests so the system stayed stable as the team continued to ship.
